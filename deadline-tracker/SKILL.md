# Deadline Tracker

Add one row to the Gravitas Deadline Tracker. Use the bundled script; do not
hand-roll Composio curl calls for writes.

## Why the script is mandatory

The write tab is literally named `[ONLY FILL THIS UP]Deadline Tracker`.
Composio's `GOOGLESHEETS_VALUES_UPDATE` rejects that real sheet name as a
"placeholder value", which repeatedly caused failed writes and timeouts. The
script avoids the bad path by resolving the sheet's numeric `sheetId`, finding
the next row from column B, and writing via
`GOOGLESHEETS_BATCH_UPDATE_VALUES_BY_DATA_FILTER` with `gridRange`.

## The sheet

Spreadsheet:
`https://docs.google.com/spreadsheets/d/1OTM4bcQzouLn69H7nvIp_Yktr_nVGJDjxkH4JBlsipY`

Columns A-K:

1. No. — formula, generated by script
2. Report — required
3. Frequency — required if unclear; examples: Campaign, Monthly, Quarterly, H1, One-Off
4. Owner — required if unclear; one of Shazan, Serene, Dula, Sky
5. Status — default `To start`; allowed: To start, Can start, Currently doing, Ongoing, Delivered
6. Waiting On — default `-`
7. EXT Deadline — required real date, e.g. `12 Aug 2026`
8. QC? — default `-`; use `QC` if needed
9. Days Left — formula, generated by script
10. Month — formula, generated by script
11. Key (auto) — formula, generated by script

## Phase 1 -- Gather fields

Ask only for missing required fields:

- Report name
- EXT Deadline
- Owner, if not clearly stated
- Frequency, if not clearly stated

Default silently unless told otherwise:

- Status: `To start`
- Waiting On: `-`
- QC?: `-`

Do not infer owner from the Discord user; people can add tasks for each other.
Do not invent a deadline.

## Phase 2 -- Dry-run the script

First run a dry-run so the next row and payload are visible without writing:

```bash
node /root/gravitas-workspace/.pi/skills/deadline-tracker/scripts/add_deadline_row.mjs \
  --report "Friso August report" \
  --frequency "Monthly" \
  --owner "Shazan" \
  --deadline "12 Aug 2026" \
  --status "To start" \
  --waiting-on "-" \
  --qc "-"
```

If the dry-run returns `ok: false`, stop and report the error plainly.

## Phase 3 -- Apply exactly once

If the dry-run looks right, run the same command with `--apply`:

```bash
node /root/gravitas-workspace/.pi/skills/deadline-tracker/scripts/add_deadline_row.mjs \
  --report "Friso August report" \
  --frequency "Monthly" \
  --owner "Shazan" \
  --deadline "12 Aug 2026" \
  --status "To start" \
  --waiting-on "-" \
  --qc "-" \
  --apply
```

The script re-checks the real next empty row immediately before writing. Do not
compute or reuse row numbers yourself.

## Phase 4 -- Confirm back

Reply with:

- Report
- Owner
- Deadline
- Row number
- Sheet link

If anything fails, say it failed. Do not answer "done" unless the script returns
`ok: true` with `dryRun: false`.
