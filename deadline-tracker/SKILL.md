# Deadline Tracker

Add or edit one row in the Gravitas Deadline Tracker. Use the bundled scripts;
do not hand-roll Composio curl calls for writes.

## Why the script is mandatory

The write tab is literally named `[ONLY FILL THIS UP]Deadline Tracker`.
Composio's `GOOGLESHEETS_VALUES_UPDATE` rejects that real sheet name as a
"placeholder value", which repeatedly caused failed writes and timeouts. The scripts avoid the bad path by resolving the sheet's numeric `sheetId`, finding
the target row from column B or an explicit row number, and writing via
`GOOGLESHEETS_BATCH_UPDATE_VALUES_BY_DATA_FILTER` with `gridRange`.

## The sheet

Spreadsheet:
`https://docs.google.com/spreadsheets/d/1OTM4bcQzouLn69H7nvIp_Yktr_nVGJDjxkH4JBlsipY`

Columns A-K:

1. No. — formula, generated by script
2. Report — required
3. Frequency — required if unclear; examples: Campaign, Monthly, Quarterly, H1, One-Off
4. Owner — required if unclear; one of Shazan, Serene, Dula, Sky
5. Status — default `To start`; allowed: To start, Can start, Currently doing, Ongoing, Delivered
6. Waiting On — default `-`
7. EXT Deadline — required real date, e.g. `12 Aug 2026`
8. QC? — default `-`; use `QC` if needed
9. Days Left — formula, generated by script
10. Month — formula, generated by script
11. Key (auto) — formula, generated by script

## Phase 1 -- Decide add vs edit

Use `add_deadline_row.mjs` when the user asks to add/create a new task/report.
Use `edit_deadline_row.mjs` when the user asks to update/edit/change status,
deadline, owner, waiting-on, frequency, QC, or report name for an existing row.

## Phase 2A -- Add: gather fields

Ask only for missing required fields:

- Report name
- EXT Deadline
- Owner, if not clearly stated
- Frequency, if not clearly stated

Default silently unless told otherwise:

- Status: `To start`
- Waiting On: `-`
- QC?: `-`

Do not infer owner from the Discord user; people can add tasks for each other.
Do not invent a deadline.

## Phase 2B -- Edit: gather target and changed fields

For edits, ask only for what is missing:

- Target row or report name to match
- The field(s) to change, e.g. status/deadline/owner/waiting-on/QC/frequency

If a report-name search matches multiple rows, the script will return candidates.
Ask the user which row to update; do not guess.

## Phase 3 -- Dry-run the script

For add dry-run:

```bash
node /root/gravitas-workspace/.pi/skills/deadline-tracker/scripts/add_deadline_row.mjs \
  --report "Friso August report" \
  --frequency "Monthly" \
  --owner "Shazan" \
  --deadline "12 Aug 2026" \
  --status "To start" \
  --waiting-on "-" \
  --qc "-"
```

For edit dry-run:

```bash
node /root/gravitas-workspace/.pi/skills/deadline-tracker/scripts/edit_deadline_row.mjs \
  --match-report "Friso H1 PCR Comfort Next" \
  --status "Currently doing"
```

Or target a known row directly:

```bash
node /root/gravitas-workspace/.pi/skills/deadline-tracker/scripts/edit_deadline_row.mjs \
  --row 30 \
  --deadline "15 Aug 2026"
```

If the dry-run returns `ok: false`, stop and report the error plainly.

## Phase 4 -- Apply exactly once

If the dry-run looks right, run the same command with `--apply`.

Both scripts re-check the target row immediately before writing. Do not compute
or reuse row numbers yourself.

## Phase 5 -- Confirm back

Reply with:

- Action: added or edited
- Report
- Changed fields for edits
- Owner/deadline when relevant
- Row number
- Sheet link

If anything fails, say it failed. Do not answer "done" unless the script returns
`ok: true` with `dryRun: false`.
